# KR 수급 데이터는 무인증 공개 소스만 사용한다

KR 투자자별 매매동향(수급) 수집에서 pykrx·KIS 등 라이브러리/API 키 기반
소스를 의도적으로 배제하고, 무인증 공개 엔드포인트만 사용한다 — 종목:
네이버 모바일 JSON(기본) + 다음 금융 JSON(fallback), 시장: 네이버 PC
페이지(단일 소스 + fail-open). 이 저장소의 "설정 없이 바로 동작, 신규
의존성 최소화" 원칙과 TW 三大法人 fetcher 선례를 따르기 위해서다.

원래 KRX 정보데이터시스템(data.krx.co.kr)을 기본 소스로 설계했으나,
2026-07-10 실측에서 전 통계 엔드포인트가 로그인 게이트로 전환된 것을
확인해(모든 통계 bld 요청이 `LOGOUT` 반환, 메뉴 로더가 "로그인 또는
회원가입이 필요합니다" 표시) 폐기했다. 이 결과 종목 수급은 KRW 금액이
아닌 주수(shares) 단위로만 조달 가능하다 — 레코드 계약의 단위
이원화(종목=주수 / 시장=KRW)는 이 제약의 직접 귀결이다.

## Considered Options

- **KRX 정보데이터시스템**: 금액+주수를 모두 제공하는 원천 통계였으나
  로그인 필수로 전환 — 기각 (2026-07-10 실측).
- **pykrx**: KRX 스크래핑을 감싼 라이브러리. 같은 로그인 게이트에 걸리는
  데다 신규 의존성이 추가되고 드리프트 대응이 외부 릴리스 주기에 묶인다 —
  기각.
- **KIS(한국투자증권) OpenAPI**: 공식이고 안정적이며 금액 데이터도 있지만
  API 키 발급·설정이 필요해 "무설정 동작" 계약을 깨고, 키 없는
  사용자에게는 기능이 조용히 비활성화된다 — 기각.
- **주수×종가 KRW 추정**: 실제 체결 단가와 다른 추정치를 금액처럼 표기하게
  된다 — 데이터 정직성 문제로 기각.

## Consequences

- 비공식 웹 엔드포인트의 형식 변경 리스크를 감수한다 — 종목은 이중
  소스(네이버+다음) + fail-open + network 스모크로 완화하고, 시장은 단일
  소스라 드리프트 시 해당 섹션이 생략된다.
- 종목 수급은 주수 단위, 시장 수급은 KRW 단위가 계약이다. 이후 공식
  소스(예: KIS 키 opt-in)가 필요해지면 fetcher 내부 소스 체인에 추가하는
  방식으로 확장한다. 정규화 레코드 계약(공개 인터페이스)은 유지한다.
